# Spot & Learn Battle 고충실도 UI/UX 레퍼런스 설계

**상태:** 사용자 방향 승인 완료  
**작성일:** 2026-07-16  
**적용 대상:** 모바일 홈, 관찰 배틀, 최종 단어·뜻 피드백, 펫 수집 화면과 여기서 파생되는 MVP 화면  
**구현 기준:** 첨부 콘셉트 이미지와 거의 흡사한 인상을 제공하되 실제 UI는 접근 가능한 네이티브 컴포넌트로 구성한다.

## 1. 목표와 비목표

### 목표

- 밝고 친근한 캐주얼 교육 게임의 인상을 첫 화면부터 일관되게 전달한다.
- 고채도 블루 헤더, 흰색 라운드 카드, 진한 네이비 타이포, 코기 탐험가 마스코트, 보상형 반짝임, 크고 입체적인 CTA를 네 화면에 공통 적용한다.
- 첨부 이미지의 정보 계층, 주요 블록 비율, 색 대비, 표면 깊이, 타이포 무게, CTA와 탭 구조, 일러스트 톤을 고충실도로 재현한다.
- 홈 → 배틀 → 단어·뜻 학습 → 보상·펫 성장의 순환을 같은 디자인 시스템 안에서 연결한다.
- 320dp급 소형 화면, 안전 영역, 200% 글자 확대, 스크린 리더, reduced motion에서도 핵심 행동과 상태를 유지한다.

### 비목표

- 이미지의 iPhone 외곽 프레임, Dynamic Island, 상태 표시줄을 앱 UI로 재현하지 않는다.
- 이미지 속 샘플 닉네임, 오탈자, 점수, 시간, 통화 잔액을 제품 규칙으로 채택하지 않는다.
- 화면 전체를 한 장의 래스터 이미지로 만들거나 래스터 이미지 안에 실제 UI 문구를 넣지 않는다.
- UI 방향을 이유로 새 통화, 현금 결제, 펫 전투 능력 또는 점수 규칙을 추가하지 않는다.
- 콘셉트 이미지 자체를 자동 픽셀 비교의 최종 기준으로 사용하지 않는다. 구현 화면을 사람 검수로 승인한 뒤 그 스크린샷을 플랫폼별 회귀 기준으로 승격한다.

### 충실도 포함 범위

- 앱 콘텐츠 영역의 수직 흐름과 주요 블록 점유율
- 블루 중심 팔레트와 블루·레드 대전 대비
- 카드 반경, 얇은 경계선, 부드러운 그림자, CTA의 눌림 턱
- 굵고 둥근 한글 중심 타이포와 tabular 점수·타이머 숫자
- 카툰 펫, 탐험·관찰·학습을 나타내는 커스텀 아이콘
- 모달 dim, 축하 캐릭터, 보상 배너가 만드는 전후 깊이
- 선택·잠금·등급·정답·오답·소유권을 색과 도형으로 함께 구분하는 방식

### 충실도 제외 범위

- 기기 베젤, Dynamic Island, 참조 상태 표시줄
- 샘플 문구와 샘플 수치의 글자 단위 복제
- 이미지 생성 과정에서 생긴 글자 왜곡과 논리적으로 맞지 않는 재화·점수
- 실제 게임 규칙, 서버 상태, 경제 계약과 충돌하는 표현

- 블루·진녹색·진빨강 표면에는 흰색 텍스트를, 노랑·밝은 코랄·민트 표면에는 네이비 텍스트를 사용한다.
- 팀, 등급, 정오답은 색만으로 표시하지 않고 아이콘, 텍스트, 테두리 모양을 함께 사용한다.
- 홈과 펫 헤더는 `primary.600 → primary.400` 세로 그라데이션을 사용한다.
- 막판 러시 HUD는 내 영역 블루와 상대 영역 레드를 중앙 타이머에서 만나게 한다.

### 타이포그래피

- 본문·숫자·버튼은 재배포 권리가 확인된 `Pretendard Variable` 한 계열을 사용한다.
- 브랜드 로고는 별도 원본 벡터 자산으로 만들며 일반 텍스트 스타일로 재현하지 않는다.
- 점수와 타이머에는 tabular 숫자를 적용해 값이 바뀌어도 폭이 흔들리지 않게 한다.

| 스타일 | 크기/행간 | 굵기 | 대표 용도 |
|---|---:|---:|---|
| `display.xl` | 40/48 | 900 | 결과 단어, 특별 보상 |
| `heading.lg` | 28/36 | 800 | 화면 제목, 대표 펫 이름 |
| `heading.md` | 22/30 | 800 | 카드 제목, 점수 |
| `body.lg` | 16/24 | 600 | CTA와 주요 설명 |
| `body.md` | 14/20 | 600 | 일반 본문 |
| `label.sm` | 12/16 | 600 | 배지와 보조 수치 |

200% 글자 확대에서 텍스트를 잘라내거나 축소하지 않는다. 카드 높이는 늘어나며, 두 열 CTA는 세로 스택으로 전환한다.

### 간격, 형태, 깊이

- 8pt 그리드를 기본으로 하고 예외는 4pt 단위로만 허용한다.
- 화면 좌우 여백 16, 카드 내부 16~20, 섹션 간격 20~24, 그리드 간격 8~12를 사용한다.
- 반경은 컨트롤 16, 일반 카드 20, 히어로·모달 24, 칩·재화 캡슐 999를 사용한다.
- 일반 카드는 1px `color.border`, `0 2 6 rgba(11,35,71,0.10)` 그림자를 사용한다.
- 강조 카드는 `0 6 16 rgba(11,35,71,0.14)`까지 허용한다.
- 주 CTA는 60~64 높이, 보조 CTA는 52~56 높이이며 3~4px의 짙은 하단 턱으로 눌림감을 표현한다.

### 아이콘과 일러스트

- 시스템 이모지를 제품 아이콘으로 사용하지 않는다.
- 기본 아이콘 24, 하단 탭 26~28, CTA 삽화 36~48을 사용한다.
- 아이콘은 둥근 끝의 2~2.5px 네이비 외곽선과 단순한 2~4색 면으로 통일한다.
- 활성 탭은 채움형, 비활성 탭은 선형 아이콘으로 구분한다.
- 코기 탐험가의 고글, 청록 스카프, 목걸이 표식, 얼굴 비율은 캐릭터 모델 시트로 고정한다.
- UI 글자와 상태 표시는 일러스트에 굽지 않고 별도 컴포넌트로 합성한다.

## 5. 화면별 설계

### `HOME_DEFAULT`

위에서 아래로 다음 순서를 고정한다.

1. 블루 브랜드 헤더와 8~15% 투명도의 발바닥·책·별 패턴
2. 프로필, 레벨 진행률, 백엔드가 정의한 재화
3. 큰 대표 펫 일러스트, 등급, 레벨, EXP를 담은 히어로 카드
4. 가장 크고 진한 `바로 대전` CTA와 코랄색 `친구와 하기` CTA
5. 랜덤 매칭, AI 연습, 친구 코드의 세 보조 카드
6. 오늘의 미션과 보상 진행률
7. “관찰로 점수 획득, 학습으로 역전” 학습 메시지
8. 홈·펫·합성·도감 하단 탭

`바로 대전`은 화면의 유일한 최상위 행동이다. 친구·AI·코드 진입은 한 단계 낮은 크기와 채도로 표시한다. 로딩 중에는 카드 형태를 유지한 skeleton을 사용하며 서버 데이터 실패 시 대표 CTA는 재시도 이유와 함께 비활성화한다.

### `MATCH_WORD_HUNT`

- 상단 고정 HUD에는 내 카드, 중앙 타이머·목표 100점, 상대 카드가 한 줄로 배치된다.
- HUD 아래 `WordSlots`, 그 아래 같은 비율의 비교 이미지 두 장, 하단 고정 액션 도크 순서를 사용한다.
- 두 이미지는 crop 없이 같은 content rect를 사용하고 zoom/pan transform을 동기화한다.
- 차이점 링의 시각 지름은 32~40이되 실제 터치 영역은 최소 iOS 44pt, Android 48dp를 보장한다.
- 내 발견은 블루 링+내 이니셜/발바닥, 상대 발견은 레드 링+상대 이니셜/돋보기로 구분한다.
- 탭 직후에는 판정 대기 ripple만 표시하고, 확정 링과 점수 변화는 서버 판정 이벤트 후 반영한다.
- 돌발 단어 미션은 중앙 1.2초 강조 카드 → 상단 미션 바 축소 순서로 전환하며 reduced motion에서는 짧은 crossfade로 대체한다.
- 하단 도크는 `정답 도전`을 주 CTA, `힌트`를 노랑 보조 CTA로 둔다. 비용 부족, 잠금, 연결 복구 중 상태는 색과 문구로 함께 표시한다.
- `FINAL_RUSH`에서는 HUD가 블루·레드 분할로 바뀌고 타이머가 코랄색으로 강조되지만 보드 위치와 터치 좌표는 변하지 않는다.

### `MATCH_MEANING_SUCCESS`

- 기존 보드를 `color.overlay`로 어둡게 하되 진행 상태가 배경에 남아 있음을 알 수 있게 한다.
- 모달 폭은 `화면 너비 - 32`, 최대 360이며 높이는 80vh 이내에서 내부 스크롤한다.
- 축하 마스코트 → 정답·보상 배너 → 완성 단어 → 뜻 질문 → 3개 선택지 → 연속 성공 → 학습 보너스 순으로 쌓는다.
- 선택지는 56~64 높이로 만들고 선택 전에는 정답을 접근성 라벨이나 컴포넌트 순서로 노출하지 않는다.
- 정답은 체크 아이콘+“정답”+보상, 오답은 X 아이콘+설명으로 표시한다.
- 필수 뜻 퀴즈 중에는 backdrop 탭과 시스템 뒤로가기로 모달을 닫지 못하며 포커스를 모달 내부에 가둔다.
- 서버 확정 전에 성공·보상 애니메이션을 재생하지 않는다.

### `PET_COLLECTION`

- 블루 헤더 아래 선택 펫, 등급, 레벨, EXP와 재화 행을 한 히어로 카드에 배치한다.
- 도감·뽑기·합성은 세그먼트 탭으로 전환하고 현재 탭을 채움형 블루로 표시한다.
- 375~599dp에서는 4열, 320~374dp에서는 3열, 600dp 이상에서는 5~6열 또는 2단 레이아웃을 사용한다.
- 일반은 녹색, 희귀는 파랑, 전설은 보라 테두리와 텍스트 배지를 함께 사용한다.
- 잠금 카드는 실루엣, 자물쇠, 구체적인 해제 조건을 함께 표시한다.
- 뽑기 패널에는 비용, 보유 포인트, 실행 가능 여부를 한눈에 보여주고 잔액 부족 시 구매 유도가 아닌 획득 경로를 안내한다.
- 합성 가이드는 재료 수, 현재 선택된 재료, 결과 등급을 아이콘과 숫자로 동시에 표시한다.

### 파생 화면

매칭, 친구방, AI 튜토리얼, 결과 화면은 네 골든 레퍼런스의 공통 컴포넌트와 토큰을 사용한다. 결과 화면은 `MATCH_MEANING_SUCCESS`의 축하 계층을, 매칭·친구방은 `HOME_DEFAULT`의 카드 계층을 재사용한다. 파생 화면은 콘셉트 이미지와의 픽셀 유사도가 아니라 디자인 토큰 사용률과 컴포넌트 일관성으로 검수한다.

## 6. 상태, 데이터 흐름, 오류 처리

### 상태 계약

모든 상호작용 컴포넌트는 `default`, `pressed`, `disabled`, `loading`, `success`, `error` 상태를 가진다. 관련 컴포넌트는 `locked`, `pending`, `offline`, `reconnecting`, `empty`를 추가한다.

### 데이터 흐름

1. 서버 snapshot/event와 로컬 접근성 설정을 feature adapter가 화면별 view model로 변환한다.
2. 화면 컴포넌트는 view model만 렌더링한다.
3. 사용자 탭은 명령 의도로 상위 feature에 전달한다.
4. 네트워크 전송 중에는 pending 피드백만 보인다.
5. 서버 확정 이벤트가 도착하면 점수, 소유 링, 단어 슬롯, 보상 상태를 갱신한다.

클라이언트는 점수·정답·보상·재화 잔액을 재계산하지 않는다. 참조 이미지와 다른 수치가 나오더라도 서버 계약을 우선한다.

### 오류와 복구

- 이미지 preload 실패: 게임 시작을 막고 실패 자산과 재시도 행동을 표시한다.
- 연결 지연: HUD를 없애지 않고 상단에 연결 복구 배너와 마지막 확정 revision을 표시한다.
- 중복 발견: 기존 소유 링을 강조하고 “이미 발견된 차이”를 텍스트로 알린다.
- 오답: 300ms 이하 shake, 오류 아이콘, 잠금 남은 시간 문구를 함께 제공한다.
- 잔액 부족: 버튼을 비활성화하고 필요한 포인트와 획득 경로를 표시한다.
- 수집 항목 없음: 빈 그리드 대신 첫 획득 경로와 AI 연습 CTA를 표시한다.
- 긴 한글·영문: 줄바꿈을 우선하고 핵심 CTA 라벨은 최대 두 줄까지 허용한다.

## 7. 모션, 햅틱, 사운드

| 피드백 | 기준 시간 |
|---|---:|
| 일반 탭·pressed | 90~120ms |
| 모달 fade/scale | 180~220ms |
| 차이점 링 확장·안착 | 180~250ms |
| 점수 count-up | 250~350ms |
| 오답 shake | 300ms 이하 |
| 정답 체크·코인·컨페티 | 650~900ms |

- pressed는 `scale(0.97)`과 하단 턱 감소로 표현한다.
- 정답에는 짧은 성공 햅틱, 오답에는 경고 햅틱을 사용하며 설정에서 각각 해제할 수 있다.
- reduced motion에서는 위치·크기 이동을 제거하고 100ms 이하 crossfade 또는 즉시 상태 전환으로 대체한다.
- 모션 설정은 서버의 `revealAt`, `claimableAt`, lock 만료 시각을 변경하지 않는다.

## 8. 접근성과 반응형

- iOS control은 최소 44×44pt, Android control은 최소 48×48dp다.
- 기본 기준 viewport는 390×844 portrait이며 320dp 너비부터 지원한다.
- landscape는 MVP 게임 플레이 범위에서 지원하지 않고 회전 시 portrait 유지 안내를 제공한다.
- 홈 인디케이터와 노치 영역은 `ScreenScaffold`가 흡수하며 하단 탭·액션 도크가 겹치지 않게 한다.
- 스크린 리더 순서는 시각 순서와 같아야 하며 점수·타이머·상태 변화는 중복되지 않는 live announcement로 전달한다.
- 모달은 포커스를 내부에 가두고 닫을 수 있는 모달만 명확한 닫기 버튼을 제공한다.
- 200% 글자 확대에서는 카드가 세로로 늘어나고 2열 CTA와 4열 펫 그리드는 각각 1열과 2~3열로 줄어든다.
- 회색조에서도 내 발견·상대 발견, 일반·희귀·전설, 정답·오답을 구분할 수 있어야 한다.

## 9. 자산·권리 계약

- 콘셉트 원본과 런타임 자산은 각각 SHA-256, 크기, 형식, 사용 화면, 출처, 생성 도구, prompt hash, 라이선스·권리 상태, 승인 시각을 기록한다. 사용자가 제공한 콘셉트처럼 원 prompt를 알 수 없는 경우 `source=USER_PROVIDED_AI_GENERATED`, `promptHash=null`, `promptAvailable=false`를 명시한다.
- 런타임 자산은 `icons`, `illustrations`, `background-patterns`, `logos`, `fonts`로 구분한다.
- 캐릭터 일러스트는 동일 모델 시트와 팔레트를 사용하고 화면마다 얼굴 비율·장비·색이 달라지지 않게 한다.
- 권리 상태가 승인되지 않은 폰트·아이콘·생성 이미지는 beta 빌드에 포함하지 않는다.
- 콘셉트 원본은 제품 자산이 아니라 시각 방향 증거로만 보존한다.

## 10. 검증 전략과 인수 기준

### 콘셉트 충실도 검수

네 레퍼런스는 기기 프레임과 생성 이미지 특유의 왜곡을 포함하므로 자동 픽셀 기준이 아니라 영역별 수동 rubric으로 비교한다. 기기 프레임·Dynamic Island·상태 표시줄을 제외한 앱 콘텐츠 영역을 같은 390×844 좌표로 정규화한 뒤 측정한다.

- 정보 계층과 주요 블록 순서가 일치한다.
- 주요 카드·CTA·HUD의 폭과 높이가 기준 viewport에서 레퍼런스 대비 ±4dp 또는 ±2% 안에 든다.
- 팔레트, 그라데이션 방향, 반경, 경계, 그림자 단계가 정의된 토큰과 일치한다.
- 타이포 크기·굵기·정렬이 같은 역할의 레퍼런스 요소와 일치한다.
- 마스코트와 아이콘의 카툰 톤, 외곽선, 색 수, 비율이 일관된다.
- P0는 주 행동·정보 계층·게임 상태가 누락되거나 오인되는 차이, 접근성 차단, 비공개 정답 노출이다.
- P1은 주요 블록 비율, 핵심 팔레트, 카드 깊이, 타입 계층, 캐릭터 정체성이 레퍼런스와 명백히 다른 차이다.
- P2는 기능·브랜드 인상을 바꾸지 않는 4dp 미만 정렬이나 장식 차이다. P0/P1은 0건이어야 하고 P2는 검토 기록과 함께 승인할 수 있다.

### 구현 후 자동 시각 회귀

- 사람 검수로 승인된 iOS·Android 구현 스크린샷을 플랫폼별 golden으로 저장한다.
- 기준 viewport는 390×844이고 320×568, 412×915를 추가 검수한다.
- 상태 표시줄, 라이브 타이머, 사용자 데이터, 애니메이션 중인 일러스트는 명시적 mask를 사용한다.
- 나머지 영역은 SSIM 0.97 이상, RGB 채널별 절대 차이 12/255 초과 픽셀 비율 5% 이하를 모두 만족해야 한다. 실패 시 사람이 diff를 검토하며 기준 이미지를 자동 갱신하지 않는다.
- `HOME_DEFAULT`, `MATCH_WORD_HUNT`, `MATCH_MEANING_SUCCESS`, `PET_COLLECTION` 네 fixture를 모두 고정 seed와 고정 시각으로 재현할 수 있어야 한다.

### 기능·접근성 인수

- 터치 대상, 200% 글자 확대, 회색조, reduced motion, 스크린 리더, 배경 전환·복귀, 재접속을 iOS·Android에서 기록한다.
- modal focus, backdrop 차단, 키보드·스크린 리더 정답 누출, disabled/loading/offline 상태를 자동 또는 명시적 수동 테스트로 검증한다.
- 시각적 재현 때문에 서버 권위, touch hitbox 공정성, 정답 비노출, 보상 원장 규칙이 훼손되지 않아야 한다.

## 12. 결정 요약

- 첨부 이미지는 제품의 고충실도 시각 방향이며 단순 분위기 참고가 아니다.
- UI는 재사용 가능한 네이티브 컴포넌트로 만들고 정적 통이미지 구현을 금지한다.
- 네 화면은 골든 레퍼런스 등급, 나머지 MVP 화면은 파생 등급으로 관리한다.
- 실제 규칙·상태·경제 값은 서버와 기존 사양을 우선한다.
- 접근성·safe area·작은 화면 때문에 필요한 재배치는 허용하되 시각 계층과 브랜드 인상은 유지한다.
- 콘셉트 비교는 수동 rubric, 승인된 구현 화면 이후의 회귀는 자동 screenshot diff로 운영한다.
