# 틀린그림찾기 아트 생성 가이드

작성 2026-08-13. 기존 79개 팩을 실측한 결과에 근거한다. **25개(32%)가 플레이 불가**였고,
원인은 전부 아래 네 가지 중 하나였다.

---

## 0. 한 줄 요약

> **B는 A를 편집한 것이어야 한다. A와 비슷한 프롬프트로 새로 생성한 것이면 안 된다.**

이 한 가지를 어기면 나머지를 아무리 잘해도 게임이 성립하지 않는다. 실패한 25개 중 최소
19개가 이 문제였다.

---

## 1. 왜 "새로 생성"이 치명적인가

두 이미지를 각각 생성하면 **모든 픽셀이 조금씩 다르다.** 조명, 질감, 원근, 선 두께가 전부
미세하게 달라진다. 그러면:

- 화면 전체가 "다른 곳"이 되어 **찾을 대상이 정의되지 않는다**
- 정작 사람 눈에 띄는 덩어리는 몇 개 없어서 **판을 끝낼 수 없다**

실측이 이걸 그대로 보여준다. `en-dilemma`는 화면의 **10.8%가 달라졌는데 찾을 수 있는
차이는 1개**뿐이었다. 변화가 넓게 얇게 퍼져서 어디를 눌러도 "여기가 그거다" 할 지점이 없다.

| 판정 | 개수 | 특징 |
| --- | --- | --- |
| 사용 가능 | 54 | 변화량 중앙값 **7.2%**, 뚜렷한 차이 5~16개 |
| 전면적으로 다름 | 12 | 변화량 **18.5~26.8%** — 사실상 다른 그림 |
| 찾을 차이 부족 | 12 | 변화량은 높은데(최대 16.5%) 뚜렷한 덩어리는 4개 이하 |
| 파일 손상 | 1 | |

**"변화량은 큰데 찾을 게 없다"** 는 조합이 재생성의 지문이다. 편집으로 만든 페어는
변화량이 작으면서 덩어리가 뚜렷하다.

---

## 2. 만드는 방법

### 2.1 절차

1. **A를 먼저 완성한다.** 이게 원본이고 다시 만들지 않는다.
2. **A를 입력으로 부분 편집한다.** 인페인팅 / 마스크 기반 img2img를 쓴다.
   - 바꿀 영역에만 마스크를 칠하고, 그 영역만 다시 그린다
   - 마스크 밖은 **원본 픽셀을 그대로 복사**해야 한다
3. **한 번에 하나씩, 8~10회 반복한다.** 한 번에 여러 곳을 바꾸면 모델이 주변까지 건드린다.
4. 저장할 때 **A와 동일한 해상도·포맷**으로 저장한다. 리사이즈나 재압축을 거치지 않는다.

### 2.2 img2img 전체 재생성은 금지

`strength 0.3`짜리 img2img를 그림 전체에 돌리는 방식은 재생성과 같다. 결과가 비슷해
보여도 모든 픽셀이 조금씩 흔들리고, 위 표의 "전면적으로 다름"으로 떨어진다.
**마스크가 없으면 쓰지 않는다.**

## 3. 차이점 설계 규칙

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 개수 | **6~12개** | 사용 가능 팩 중앙값 8개. 5개 미만은 자동 거부 |
| 크기 | 지름이 그림 폭의 **12% 이상** | 44pt 탭 타겟(WCAG 2.5.8). 정규화 반지름 0.06 |
| 최대 크기 | 한 변이 그림의 **25% 이하** | 그보다 크면 "차이"가 아니라 화면 개편 |
| 밀도 | 탭 지점 주변의 **35% 이상**이 실제로 달라야 함 | 옅은 변화는 눌러도 못 찾는다 |
| 간격 | 두 차이점의 중심 거리 ≥ 두 반지름의 합 | 겹치면 한 번의 탭이 어느 쪽인지 모호해진다 |
| 총 변화량 | 화면의 **2~15%** | 사용 가능 팩 범위. 18% 넘으면 자동 거부 |

현재 54개 팩 중 **50개에 겹치는 히트박스가 있다**(전체 쌍의 6.8%). 새로 만들 때는 차이점을
화면에 고르게 흩어야 한다.

### 3.1 좋은 차이점 / 나쁜 차이점

**좋다** — 경계가 뚜렷하고 국소적인 변화

- 물체 색 교체 (청록 큐브 → 금색 큐브)
- 물체 추가/삭제 (책상 위 사과 하나 없애기)
- 물체 교체 (연필 → 초록 책)
- 개수 변경 (액자 속 곰 2마리 → 3마리)
- 방향/자세 반전 (시계 바늘, 인물이 든 물건)

**나쁘다** — 넓고 옅은 변화

- 전체 색조·채도·밝기 조정
- 하늘, 벽, 바닥 같은 넓은 면의 질감 변경
- 그림자 길이나 광원 위치
- 아주 작은 디테일 (1~2% 크기의 점, 무늬 한 칸)
- 원근이나 카메라 각도

## 4. 반드시 피할 것

**구도 가이드 격자.** 생성기가 삼분할선을 그림에 구워 넣는 경우가 있다. `en-camaraderie-campfire-a`가
그랬고, 짝인 B에는 없어서 **선 자체가 차이점처럼 보였다.** 검토에서 놓치기 쉽다 — 선이 얇아
배경으로 읽힌다. 반드시 `content:art:grid:check`로 확인한다.

**워터마크·서명·프레임.** 위와 같은 이유.

**텍스트.** 그림 속 글자는 생성기가 매번 다르게 쓴다. 의도치 않은 차이점이 무더기로 생긴다.

**한쪽만 리사이즈/재압축.** A와 B의 해상도나 압축률이 다르면 전체가 미세하게 달라진다.

---

## 5. 검증 (승인 전 필수)

```bash
pnpm content:art:grid:check      # 구도 격자가 구워진 이미지 탐지
pnpm content:hitboxes:derive     # 그림에서 실제 차이점을 계산하고 판정
```

두 번째 명령이 팩별로 `usable` 여부와 이유를 내놓는다. 출력에서 확인할 것:

- `IMAGES_DIFFER_GLOBALLY` → §1 위반. 재생성했다는 뜻이니 **편집 방식으로 다시 만든다**
- `TOO_FEW_DIFFERENCES` → 뚜렷한 차이가 5개 미만. 차이점을 더 크고 분명하게 추가한다
- `differences per pack`이 6~12 범위인지
- 의도한 차이점 개수와 계산된 개수가 **일치하는지** — 다르면 의도하지 않은 변화가 섞였다

마지막 항목이 특히 중요하다. "10개를 바꿨는데 16개가 검출됐다"면 편집이 주변으로 번진 것이다.

## 6. 프롬프트 예시

**A 생성** — 물체가 또렷하고 배경이 단순한 장면을 요구한다.

```
A cozy pottery studio, isometric view, flat vector illustration,
distinct separated objects on shelves and table, clean solid colors,
no text, no watermark, no grid lines, plain background, 1024x1024
```

`no text, no watermark, no grid lines`를 빼먹지 않는다.

**B 편집** — A를 입력으로, 마스크를 씌우고 한 번에 하나씩.

```
[input: A.png] [mask: 손수레 영역만]
change the wheelbarrow color from red to yellow,
keep everything else pixel-identical
```

## 7. 기존 79개 팩에 대해

54개만 사용 가능하고 나머지는 데일리에서 제외돼 있다. 제외된 25개를 되살리려면 **A를 원본으로
두고 B만 편집 방식으로 다시 만들면 된다.** A는 대부분 문제가 없다.

다만 드래프트가 `publicContent.imageA.sha256`으로 이미지를 고정하고 있어, 아트를 교체하면
해시·매니페스트·승인 절차를 함께 갱신해야 한다. B만 바꾸는 경우에도 마찬가지다.
