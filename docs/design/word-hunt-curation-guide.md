# 워드헌트 큐레이션 가이드

**대상:** `content/learning/word-hunts.curated.v1.json`을 채우는 사람(또는 에이전트).

워드헌트는 **"프롬프트가 이름을 부르면 플레이어가 그림에서 그 물건을 눌러 찾는"** 미션이다.
5초 창 동안 보드를 가로채고, 놓치면 그걸로 끝이다.

---

## 왜 이건 자동화가 안 되는가

차이점 히트박스는 두 이미지를 빼면 나온다. 계산이다.
**워드헌트는 계산이 아니다.** "프리즘이 어디 있나"는 그림을 봐야 안다.

그래서 이 파일은 유일하게 **사람이 눈으로 놓는** 콘텐츠다. 동시에 조용히 틀리기 가장 쉬운
콘텐츠이기도 하다. 틀리면 **없는 것보다 나쁘다**:

> 프롬프트가 물건 이름을 부른다 → 플레이어가 그 물건을 누른다 → 게임이 "빗나갔다"고 한다.

드래프트(`content/learning/drafts/*.json`)에 이미 `wordHunts`가 있지만 **절대 쓰지 않는다.**
315개 히트박스 중 286개가 차이점 좌표를 그대로 복사한 것이고, 그 차이점 좌표조차 아트 위에
있지 않다(측정: 손으로 적은 차이점 좌표의 49%만 실제 차이점에 얹힌다).

---

## 좌표계

- 원점 **좌상단**, `cx`/`cy`/`r` 모두 **원본 이미지 기준 0..1 정규화**
- 화면 크기와 무관하다. 이미지가 1024×1024든 1536×1024든, **비율로만 읽는다**
- 소스는 `content/learning/source/<pack-key>-a.png` (**`-a`를 본다.** `-b`는 편집본이다)

예: 1024폭 이미지에서 가로 615px 지점 → `cx = 615 / 1024 = 0.600`

---

## 규칙 (검증기가 강제한다)

```bash
node tools/content/check-word-hunts.mjs
```

| 규칙 | 이유 |
|---|---|
| `r >= 0.062` | 390pt 기준 보드는 358pt 폭. 44pt 탭 최소치가 곧 이 반지름이다 |
| `cx - r >= 0`, `cx + r <= 1` (cy도 동일) | 프레임에 잘리면 손가락 밑 실제 크기가 반지름보다 작아진다 |
| 같은 팩의 두 목표는 `거리 > r1 + r2` | 겹치면 한 번의 탭이 어느 쪽인지 모호해진다 |
| 팩당 **정확히 3개**, 순서는 `NORMAL, NORMAL, SPECIAL` | 룰셋 스케줄(16-22초 / 34-42초 / 60초)에 **인덱스로** 짝지어진다 |
| `missionId`는 kebab-case, 팩 안에서 유일 | |

**검증기가 못 잡는 단 하나가 이 작업의 전부다: 좌표가 정말 그 물건 위에 있는가.**

---

## 목표를 고르는 법

**좋은 목표**

- **이름이 하나로 떨어진다.** "우산", "트로피", "나침반". 보자마자 무엇을 찾을지 안다
- **화면에서 반지름만큼 실제로 크다.** `r = 0.07`이면 지름 14%다. 그만큼 차지하는 물건이어야 한다
- **그 그림에 하나뿐이다.** 화분이 여섯 개면 "화분"은 나쁜 프롬프트다
- **A와 B 양쪽에 같은 자리에 있다.** 히트박스는 양쪽 보드에 같은 좌표로 들어간다.
  **차이점으로 편집된 물건은 고르지 않는다** — B에서 사라졌거나 색이 바뀌었을 수 있다

**나쁜 목표**

- 배경 질감("하늘", "잔디"), 세거나 지목할 수 없는 것
- 가장자리에 걸친 것 (`cx - r < 0`)
- 다른 목표와 붙어 있는 것
- 그림에 여러 개 있는 것

**난이도 순서:** 1번은 **눈에 바로 띄는 큰 것**(16-22초에 온다), 3번 SPECIAL은
**조금 더 찾아야 하는 것**. 다만 SPECIAL도 *반드시 찾을 수 있어야* 한다 — 어려움은
"작아서 안 보임"이 아니라 "복잡한 곳에 있음"으로 만든다.

---

## 프롬프트 문구

- **한국어로 쓴다.** 팩 키가 `en-`이어도 그렇다. 헌트는 *읽기* 시험이 아니라 *찾기* 시험이고,
  영어 단어를 모르면 그림을 볼 기회조차 없어진다
- 짧은 명사구: `우산`, `석등`, `불가능한 정육면체`
- 문장으로 쓰지 않는다 (`우산을 찾으세요` ✗)

---

## 형식

`packs` 아래에 팩 키로 넣는다:

```json
"en-3d-serenity": [
  { "missionId": "serenity-bridge",  "kind": "NORMAL",  "publicPrompt": "다리",   "cx": 0.479, "cy": 0.771, "r": 0.09  },
  { "missionId": "serenity-gazebo",  "kind": "NORMAL",  "publicPrompt": "정자",   "cx": 0.723, "cy": 0.557, "r": 0.09  },
  { "missionId": "serenity-rowboat", "kind": "SPECIAL", "publicPrompt": "나룻배", "cx": 0.859, "cy": 0.806, "r": 0.075 }
]
```

`missionId`는 `<팩을 알아볼 짧은 말>-<물건>` 형태로 짓는다.

---

## 절차

1. `content/learning/source/<key>-a.png`를 **본다**
2. 위 기준으로 물건 3개를 고른다
3. 각 물건의 중심을 비율로 읽고, 물건을 덮되 이웃을 침범하지 않는 `r`을 정한다
4. `node tools/content/check-word-hunts.mjs`를 돌린다. **초록이 될 때까지 고친다**
5. 아트를 바꿨거나 팩을 추가했으면 `pnpm content:preview:registry`로 데일리 풀을 다시 굽는다

## 마지막 한 줄

검증기가 초록이어도 **좌표가 물건 위에 있는지는 아무도 확인해 주지 않는다.**
확신이 없으면 그 물건을 버리고 더 확실한 걸 고른다. 헌트가 2개인 팩은 없느니만 못하지
않지만, **못 누르는 헌트가 하나 있는 팩은 없느니만 못하다.**
