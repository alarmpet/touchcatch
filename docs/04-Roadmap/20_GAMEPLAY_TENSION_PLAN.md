# 게임플레이 재미 계획서 — 페이아웃과 압박

**작성일:** 2026-08-17 · **대상:** 학습 루프(`apps/mobile/src/learning-demo/`)와 펫 획득(`apps/mobile/src/features/pets/`)

**방향:** 남녀노소가 하는 학습 게임이되, 슬롯·파친코·룰렛처럼 화려하고 중독성 있는 손맛.

---

## 먼저 나눠야 할 두 가지

카지노에서 가져올 것은 **연출**이지 **경제**가 아니다. 이 구분이 이 문서 전체를 관통한다.

| | 가져온다 | 가져오지 않는다 |
|---|---|---|
| **연출** | 기대 연장, 단계 상승, 천장 미터, 코인 폭발, 상승 음계, 연쇄 | — |
| **경제** | — | 유료 뽑기 압박, 손실 추격, 조작된 니어미스 |

이유는 두 가지고, 둘 다 실용적이다.

**첫째, 이 앱은 이미 확률형 아이템을 다룬다.** 60/25/10/4/1%를 화면에 표시하고 있고
(`DailyFreeDraw`), 한국 게임산업법의 확률 공개 요건은 그걸로 충족된다. 유료 무작위성과
손실 추격을 아동 대상 학습 앱에 얹는 순간 성격이 완전히 달라진다. **지금 위치가 좋은
위치다.**

**둘째, 그리고 이게 더 중요한데 — 중독성을 지갑이 아니라 학습 루프에 붙이는 게 실제로
더 잘 먹힌다.** 파친코의 매력은 돈이 아니라 구슬이 쏟아지는 광경이다. 슬롯의 매력은
당첨금이 아니라 릴이 멈추기 직전의 0.8초다. **그 0.8초는 공짜고, 우리 게임에서는
"차이를 하나 찾았을 때"에 붙는다.**

즉 목표는 이것이다: **아이가 단어를 강박적으로 찾게 만들되, 강박적으로 결제하게
만들지는 않는다.**

## 지금 무엇이 밋밋한가

### 1. 뽑기 연출이 620밀리초다

`PetReveal.tsx` 전체가 이렇게 동작한다:

```
SEALED → (620ms) → REVEALED
  □                  ✦
```

상자 글리프가 별 글리프로 바뀐다. 그게 전부다. **기대도, 단계 상승도, 폭발도 없다.**
전설(1%)과 일반(60%)이 같은 620ms를 쓰고 글리프 하나만 다르다.

`revealEmphasis`는 이미 `QUIET / NOTABLE / CELEBRATE` 세 등급을 계산해 놓는다.
**세 등급이 전부 글리프 한 글자로 렌더된다.**

### 2. 천장이 보이지 않는다

`config/economy.v1.json`에 완결된 피티 시스템이 있다:

```
pitySeriesId: "pity-50-150-v1"
thresholds:   rareOrBetter 50 · legendary 150
하드 피티 우선순위 · 리셋 규칙 · 오버라이드 규칙 전부 정의됨
```

**슬롯머신이 잭팟 미터를 숨기지 않는 이유가 있다. 그게 다음 판을 당기게 만드는 장치다.**
지금은 카운터가 서버에만 있고 플레이어는 자기가 천장에 얼마나 가까운지 모른다.

### 3. 학습 루프에 페이아웃 감각이 없다

차이를 하나 찾으면:

- 링이 하나 뜨고 (`pulseStyle`, 0.2 크기)
- 글자가 슬롯으로 날아가고 (`LetterFlight`, 560ms)
- 소리가 한 음 올라간다 (`findToneStep`, 8단계)

**소리만 고조된다.** 1번째 발견과 7번째 발견의 화면이 똑같다. 슬롯으로 치면 릴은
돌아가는데 화면은 정지해 있는 상태다.

### 4. 질 수가 없어서 이길 맛도 없다

`LearningDemoScreen.tsx:356` 주석이 스스로 밝힌다 — *"it is a bonus timer, not a threat."*
시계가 0이 돼도 판이 계속된다. **위험이 0이면 페이아웃도 감흥이 없다.** 카지노가
긴장을 파는 이유가 이것이다.

더해서, 룰셋에 정의돼 있는데 싱글 플레이가 재생하지 않는 것들:

| 룰셋(`config/ruleset.v1.json`) | 싱글 플레이 |
|---|---|
| `finalRushStartsAtMs: 60000` — 파이널 러시 | 없음 |
| `suddenDeathMs: 10000` — 서든데스 | 없음. **드래프트 79개가 히트박스를 싣고 다니는데도** |
| `wordHuntMs: 5000` — 5초 창 3회 | 리듀서에 단계는 있으나 스케줄러가 없다 |
| `maxWrongAttempts: 3` | 무제한 |

## A. 페이아웃 계통 — 화려함이 들어갈 자리

### A1. 기대를 늘린다 (슬롯의 제1 원리)

**결과가 좋을수록 연출을 길게 끈다.** 결과는 서버가 이미 정해서 보내므로 연출 길이를
결과로 결정해도 조작이 아니다 — 슬롯이 정확히 그렇게 동작한다.

```
일반   620ms   짧고 담백하게
고급   900ms
희귀  1400ms   여기서부터 링이 돌기 시작
영웅  2100ms   템포 상승, 화면 가장자리 발광
전설  3200ms   전부 멈췄다가 터진다
```

**끊을 수 있어야 한다.** 탭하면 즉시 결과로 건너뛴다. 3초를 매일 강제로 보게 하면
연출이 아니라 통행세가 된다.

### A2. 등급을 거쳐 올라간다 (이 문서에서 효과가 가장 큰 항목)

전설이 나올 때 곧바로 전설을 보여주지 않는다. **등급 사다리를 밟고 올라간다.**

```
일반 … 고급 … 희귀 … 영웅 … 전설!
 ↑     ↑     ↑     ↑      ↑
각 단계마다 색이 바뀌고, 음이 올라가고, 한 번 멈칫한다
```

한 단계 올라갈 때마다 "여기서 멈추나?" 하는 순간이 생긴다. **이게 니어미스의 정직한
형태다.** 결과를 왜곡하지 않고, 이미 확정된 결과에 이르는 경로를 극적으로 만들 뿐이다.

`rarityGradients`가 이미 5등급 램프를 갖고 있어서 색은 그대로 쓰면 된다.

### A3. 천장 미터를 잭팟 미터로 보여준다

```
희귀 천장까지  ▓▓▓▓▓▓▓░░░  38 / 50
전설 천장까지  ▓▓░░░░░░░░  27 / 150
```

**정직하면서 동시에 가장 강력한 리텐션 장치다.** 확률 공개 의무와도 같은 방향이다.
천장이 가까워지면 미터가 빛나고 박동한다.

### A4. 찾기를 한 번의 스핀으로 만든다

차이를 하나 찾는 순간이 곧 레버를 당기는 순간이다. 지금 있는 조각을 그대로 쓴다:

| 지금 | 바꾼 뒤 |
|---|---|
| 링 하나 (0.2 크기) | 링 + 코인/파티클 방사, 연속 발견마다 커진다 |
| 글자 비행 560ms | 착지에 슬롯 팝 + 화면 가장자리 섬광 |
| 소리 8단계 상승 | **화면도 8단계 상승** — 색이 뜨거워지고 링이 커진다 |
| 콤보 표시 없음 | `×3` `×5` `×8` 칩, 8연속에서 한 번 터진다 |

**소리가 이미 8단계로 올라가고 있다. 화면이 따라가기만 하면 된다.**

### A5. 연쇄

빠르게 연속으로 찾으면 연쇄로 묶는다. 퍼즐 게임의 캐스케이드와 같다.

콤보가 끊기는 조건은 **시간**이지 오답 탭이 아니다 (예: 4초 안에 다음 발견). 빗나간
탭으로 콤보를 끊으면 찍어보는 아이를 벌하게 된다.

### A6. 룰렛 — 오늘의 카테고리

홈의 모드 선택은 지금 정적인 3행이다. **하루 한 번 돌리는 휠**로 바꾸면 매일 여는
이유가 생긴다. 나온 카테고리에 그날 보너스 배율이 붙는다.

정직하게: 휠은 **무엇을 플레이할지**를 고르지 보상을 고르지 않는다. 아이가 원하면
직접 고르는 길은 항상 열어둔다.

## B. 압박 계통 — 페이아웃이 의미를 갖게 하는 것

**A만 하면 화려한 화면보호기가 된다.** 위험이 있어야 보상이 보상이 된다.

### B1. 시계를 실제 마감으로

`playingMs: 75000`이 0이 되면 FIND가 닫히고 정답 단계로 넘어간다. 60초에 **파이널
러시** — 시계가 커지고 박동하고, 가장자리에 경고색이 스미고, 배경음이 `RUSH`로 바뀐다
(`music-context`에 무드 전환이 이미 있다).

**학습은 지킨다.** 시간이 끝나도 정답 입력과 힌트는 열려 있다. 닫히는 건 속도 보너스뿐이다.

### B2. 서든데스 — 이미 있는 데이터를 재생한다

마감 시점에 다 못 찾았으면 **10초, 목표 하나.** 드래프트 79개 전부에
`privateSolution.suddenDeath` 히트박스가 있다. **신규 콘텐츠 0, 파이프라인 무변경.**

이게 A2와 함께 비용 대비 효과가 가장 좋다.

### B3. 워드헌트 스케줄러

리듀서에 `START/OPEN/END_WORD_HUNT`가 이미 있다. 룰셋대로 도는 스케줄러만 없다 —
NORMAL 2회 + SPECIAL 1회, 창 5초, 읽기 유예 1.2초. **5초 창은 그 자체로 긴장이고,
판을 가로채서 리듬을 끊는다.**

### B4. 깎이는 배율을 실시간으로

지금은 판이 끝난 뒤에 `×1.42`를 통보받는다. **내려가는 숫자를 보는 것과 결과를
통보받는 것은 다른 경험이다.**

힌트도 랭크전과 같이 **15초 차감**(`hint-policy.v1.json`의 `penaltyPerStep: 15000`)으로
통일한다. 배율보다 즉각적이고, 누르는 순간 시계가 뛰는 게 보인다.

## 남녀노소가 건다는 제약

이 방향에서 가장 쉽게 어긋나는 지점이다.

- **소리 없이도 전부 읽혀야 한다.** 무음으로 하는 사람이 다수다. 8단계 음계에는 반드시
  8단계 시각 대응을 둔다.
- **반사신경만으로 갈리지 않게 한다.** 파이널 러시는 점수를 가르되 학습을 막지 않는다.
- **연출은 건너뛸 수 있어야 한다.** 3초 전설 연출도 탭 한 번에 끝난다.
- **깜빡임을 조심한다.** 초당 3회 이상 명멸하는 전체화면 효과는 넣지 않는다. 광과민성
  발작 유발 기준이다.
- **작은 글씨에 정보를 넣지 않는다.** 콤보 숫자, 천장 카운터는 크게.

넣을 수 있다. 4번부터 룰이 움직인다.

## 성공 판정

숫자를 박아두지 않으면 "더 화려해졌다"로 끝난다.

- **재방문율**이 올라간다 — 천장 미터와 룰렛이 작동한다는 뜻
- **판당 발견 속도**가 올라간다 — 스핀 감각이 붙었다는 뜻
- **마지막 15초 발견 비율**이 올라간다 — 파이널 러시가 작동한다는 뜻
- **연출 스킵률**을 본다 — 높으면 연출이 통행세가 된 것이다
- **판 완주율은 떨어지지 않아야 한다**

마지막 항목이 나머지보다 우선한다. **화려함을 얻으려다 학습을 잃으면 잘못 만든 것이다.**

## 선행 조건

점수·순위에 영향을 주는 항목(B1·B2·B3·B4)은 `packages/contracts`의 룰에 상수를 먼저
넣고 **데모와 서버가 같은 값을 읽게** 해야 한다. 데모에만 하드코딩하면 서버 검증
경로(`RULE-013`)로 갈 때 랭킹이 갈린다.

순수 연출 항목(A1·A2·A4·A5)은 이 제약을 받지 않는다. 그래서 순서에서 앞에 있다.
